# Dataviz lab

Claude's visualization lab for the dissertation: the Visibility Atlas (`motion/explorer.html`, published on the author's site at https://armenkaprelian.github.io/atlas/ since 29 October 2026; the claude.ai artifact https://claude.ai/artifact/19DNAFozq23ng4qaD18m7n points there since its v40, `motion/pointer/atlas-moved.html`) and the explainer (`motion/explainer.html`). Sessions on the atlas or the explainer start here.

## Read first

- `motion/README.md`: the record of every round, the data passes, the tools and the publishing history; its last round entry is the latest.
- `design/principles.md`: the author's design rules. Read it before any visual work.
- `motion/review/`: round notes, proposals, measurements and review exports.

## Standing rules

- Publish only on the author's word.
- Frames first: any change with a visible or behavioural effect is shown as before/after frames and approved before it is committed. One exception (the author's rule of 28 October 2026): a wording or link change the author asks for in specific terms is approved by the request. When its proof shows only those strings changed, in their own panel, it is committed without a separate frames round, and its crop sheet goes into the next publish review. Layout, colour, data and behaviour changes keep frames first.
- Proof by `motion/tools/change-proof.py` (the author's rules of 27 October 2026, round 18, and 28 October 2026, round 19). A refactor whose run against the build before it comes out "identical" needs no frames. A change whose run shows only the strings it names changed, and frames that differ only in the panels that hold them (and in the side-column cards below them, which move with them), never in the map outside its panels, is reviewed from the run's crop sheet. A change whose run shows its text and frame differences staying inside the header or the footer (links, labels, hover and focus behaviour there), never in the map, the cards or the overlays, is reviewed from the crop sheet plus before/after frames of any new hover or focus states. Every other change keeps frames first. No change needs an audit before its review (2 November 2026); the publish gate's full run stays for every publish.
- Work directly on `main`: no branch, worktree or forked session. Commit at each checkpoint and push after each commit.
- Records (28 October 2026): a round's entry in `motion/README.md` stays at about 15 lines, covering what changed, the proof and the author's decision. Detail goes in a note in `motion/review/`.
- Audits (26 October 2026; the review-gate audit retired on the author's word of 2 November 2026). The one required audit is the publish gate's full run with `audit-five.sh`. While building, an audit is optional, at the widths the session judges useful (`motion/tools/atlas-audit.py --widths 1600`, or `motion/tools/audit-five.sh --widths 1600,400` for a layout change, since most findings have come at 400 px). A publish-gate finding is fixed before the publish, and a fix with a visible effect goes frames first. The audit serves `motion/` itself when nothing answers at its address, and `change-proof.py --base COMMIT` sets up and serves both builds itself (28 October 2026).
- A publish needs a full run on the final build, all four widths (400, 1,200, 1,600 and 2,000 px; 768 px dropped by the author on 1 November 2026, after a tally of 29 recorded runs in which it found nothing of its own) in one run of `audit-five.sh`, with zero findings. Targeted re-runs (`--widths`) never count for a publish. A finding that shows only when widths run together, and not in its width's solo re-run, is noted the first time; once its check has shown that way in an earlier run, it counts (`motion/build/audit/parallel-only.json` keeps the record). A finding from one check at every width gets no solo re-run unless that check is on the record (28 October 2026).
- A text-only fix after a passing publish gate (29 October 2026): when the full full audit passed on commit X and the final build differs from X only in text strings, `publish.sh --audited X` counts that audit for the publish. `tools/audit_carry.py` refuses unless X's pass is recorded, the shipped sources differ from X only inside string literals, the text rules pass, and `change-proof.py --base X` shows no new rule hit, no change in the map and frame changes only in panels that hold the changed text. The proof shoots 1,600 and 400 px only, so a visible string that may rewrap at other widths takes the full audit. Any other change takes the full audit.
- Publish dates are UTC days (28 October 2026). The REFERENCES panel's CORRECTIONS section was removed on the author's word on 30 October 2026, so `motion/tools/publish-set.py --dates` reports only the publish day.
- Batches (the author's rule of 1 November 2026, after round 32): several small changes may be reviewed as one batch from one review page. Each change keeps its own proof by `change-proof.py`, named by the panels it touches, and frames first where its rule asks. The publish gate's full run audits the combined build. A finding in a batch is attributed by the audit's state and element and fixed before the publish; a change the author declines is reverted and the batch proved again. The publish gate is unchanged.
- Changes that arrive while an audit is running wait for the next run. A running audit is never stopped to fold them in.
- Every tool that makes a temporary browser profile removes it when it finishes (`/tmp` is a tmpfs here), and `scripts/lab-run.sh` and `audit-five.sh` warn about idle ones (`motion/tools/stale_profiles.py`) without deleting them.
- Heavy jobs (the author's rule of 2 November 2026). Any R or DuckDB job that reads RFSD records or other firm-level inputs, a one-off count included, runs through `scripts/lab-run.sh` with a `--max` sized to it. It connects with `lab_duck_connect()` after `lab_init()`, so DuckDB's limits apply and its spill files go to `/var/tmp`. The launcher's sandbox hides `/tmp`, so a one-off script goes in `motion/build/` (ignored by git), never in the session scratchpad. A plain `Rscript` started from a Claude session runs in the Claude app's own process group, and when the kernel kills it for memory, systemd stops the whole app and every session in it, as on 1 November 2026; under the launcher, only the lab's unit dies.
- Build the publish set with `motion/tools/publish-set.py`. It never ships identifiers, and it names only firms on the five lists. Publish with `motion/tools/publish.sh`: the date check, the publish gate, `publish-set.py --write`, the publish copy and the site's import, stopping at the first failure. `publish.sh --push` makes the site public, only on the author's word (28 October 2026); it also pushes site-only changes, and runs `site-check.py` first (29 October 2026).
- Lab tools print their help for `-h`, and a tool that writes to `data/` or `publish/` writes only with `--write`; without it, it checks and reports (28 October 2026).
- Measure speed in the author's own Brave, with the window in front and live.
