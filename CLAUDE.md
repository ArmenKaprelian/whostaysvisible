# Dataviz lab

Claude's visualization lab for the dissertation: the Visibility Atlas (`motion/explorer.html`, published on the author's site at https://armenkaprelian.github.io/atlas/ since 29 October 2026; the claude.ai artifact https://claude.ai/artifact/19DNAFozq23ng4qaD18m7n points there since its v40, `motion/pointer/atlas-moved.html`) and the explainer (`motion/explainer.html`). Sessions on the atlas or the explainer start here.

## Read first

- `motion/README.md`: the record of every round, the data passes, the tools and the publishing history; its last round entry is the latest.
- `design/principles.md`: the author's design rules. Read it before any visual work.
- `motion/review/`: round notes, proposals, measurements and review exports.

## Standing rules

- Publish only on the author's word.
- Frames first: any change with a visible or behavioural effect is shown as before/after frames and approved before it is committed. One exception (the author's rule of 28 October 2026): a wording or link change the author asks for in specific terms is approved by the request. When its proof shows only those strings changed, in their own panel, it is committed without a separate frames round, and its crop sheet goes into the next publish review. Layout, colour, data and behaviour changes keep frames first.
- Proof by `motion/tools/change-proof.py` (the author's rules of 27 October 2026, round 18, and 28 October 2026, round 19). A refactor whose run against the build before it comes out "identical" needs no frames. A change whose run shows only the strings it names changed, and frames that differ only in the panels that hold them (and in the side-column cards below them, which move with them), never in the map outside its panels, is reviewed from the run's crop sheet and needs no audit at the review gate. A change whose run shows its text and frame differences staying inside the header or the footer (links, labels, hover and focus behaviour there), never in the map, the cards or the overlays, needs no audit at the review gate either: it is reviewed from the crop sheet plus before/after frames of any new hover or focus states. Every other change keeps frames first and a review-gate audit at the widths it can affect. The publish gate's full five-width run stays for every publish.
- Work directly on `main`: no branch, worktree or forked session. Commit at each checkpoint and push after each commit.
- Records (28 October 2026): a round's entry in `motion/README.md` stays at about 15 lines, covering what changed, the proof and the author's decision. Detail goes in a note in `motion/review/`.
- Audits (26 October 2026; the review gate narrowed on 28 October 2026). While building, audit at 1,600 px only (`motion/tools/atlas-audit.py --widths 1600`). At the review gate, a change the proof rule does not exempt is audited only at the widths it can affect, 1,600 and 400 px at least (`motion/tools/audit-five.sh --widths`). At the publish gate, the full five-width audit with `audit-five.sh`. The audit serves `motion/` itself when nothing answers at its address, and `change-proof.py --base COMMIT` sets up and serves both builds itself (28 October 2026).
- A publish needs a full run on the final build, all five widths in one run of `audit-five.sh`, with zero findings. Targeted re-runs (`--widths`) never count for a publish. A finding that shows only when widths run together, and not in its width's solo re-run, is noted the first time; once its check has shown that way in an earlier run, it counts (`motion/build/audit/parallel-only.json` keeps the record). A finding from one check at every width gets no solo re-run unless that check is on the record (28 October 2026).
- A text-only fix after a passing publish gate (29 October 2026): when the full five-width audit passed on commit X and the final build differs from X only in text strings, `publish.sh --audited X` counts that audit for the publish. `tools/audit_carry.py` refuses unless X's pass is recorded, the shipped sources differ from X only inside string literals, the text rules pass, and `change-proof.py --base X` shows no new rule hit, no change in the map and frame changes only in panels that hold the changed text. The proof shoots 1,600 and 400 px only, so a visible string that may rewrap at other widths takes the full audit. Any other change takes the full audit.
- Publish dates are UTC days (28 October 2026). Before the publish gate's run, `motion/tools/publish-set.py --dates` checks that a new CORRECTIONS entry carries the publish day and that no published entry already holds that day; the publish set refuses otherwise.
- Changes that arrive while an audit is running wait for the next run. A running audit is never stopped to fold them in.
- Every tool that makes a temporary browser profile removes it when it finishes (`/tmp` is a tmpfs here), and `scripts/lab-run.sh` and `audit-five.sh` warn about idle ones (`motion/tools/stale_profiles.py`) without deleting them.
- Build the publish set with `motion/tools/publish-set.py`. It never ships identifiers, and it names only firms on the five lists. Publish with `motion/tools/publish.sh`: the date check, the publish gate, `publish-set.py --write`, the publish copy and the site's import, stopping at the first failure. `publish.sh --push` makes the site public, only on the author's word (28 October 2026); it also pushes site-only changes, and runs `site-check.py` first (29 October 2026).
- Lab tools print their help for `-h`, and a tool that writes to `data/` or `publish/` writes only with `--write`; without it, it checks and reports (28 October 2026).
- Measure speed in the author's own Brave, with the window in front and live.
