# Round 18 pass: cheaper proofs for the atlas's usual edits

A pass over the Visibility Atlas (v38, `main` at 292492d), run on 27 October 2026 under the approved plan: tools and structure that make a text fix, a data refresh and a new layer or card cheaper to prove, round 17's page-text fixes as their first real use, and a checked intake for exported tables. Every change is a numbered patch, built and proven on a trial copy in `motion/build/round-18/` (the trial on port 8782, HEAD's files as the base on 8783, the trial before the text fixes on 8784). Nothing in the lab's tracked files changed except this report and the tracker's row, and nothing was published.

## The page for you

Approve all, or by number. Patches 1 to 12 change nothing on screen, which the proofs below show. Patch 13 holds round 17's text fixes, and you can approve or decline each by its number (T01 to T22). The local review page, `review/2026-10-27-round-18-pass.html`, shows every changed frame before and after.

1. **One command proves a change** (`tools/change-proof.py`). Against a copy of the build before the change, it lists the strings that changed in 144 states at 1,600 and 400 px. It frames every layer, card, pop-out, the footer, REFERENCES and the legend in both themes, names the regions that differ and the panels they touch, checks the on-screen text rules, and writes one crop sheet. Two runs of one build give "identical" (440 of 440 frames). This makes every kind of edit cheaper to prove. Risk: low, new tool.
2. **The glossary is checked against its rebuild** at every audit (`glossary_build.py --check`). A text fix that touches a sentence the glossary quotes is caught at once. Risk: low.
3. **The publish set checks the data twins.** Every `.js` twin must hold its JSON's data, and every JSON must match the hash its provenance recorded, so a stale twin after a data refresh is refused without a browser run. It also names the twins neither page loads (today `industry-city.js`, 4.3 MB). Risk: low.
4. **One port of the page's number formatting** (`tools/jsfmt.py`) for the wire, profile and guide checkers. `wire_check.py` rounded exact ties to even and negative halves away from zero, unlike the page, which a data refresh could turn into a false finding. Risk: low.
5. **The audit reads from the data what a refresh can change:** the first and latest data years, the anniversary days, the anchor pair's distance, the profile year, and the search hits, now checked against the names. The wire's speed stays pinned at 60 px/s, a design value no refresh changes. Risk: low.
6. **Duplicate audit states removed:** `mixdef2`, and ten Firms-view states that gave the same results on both renderers (checked) now run once. Two fixed waits are polled. This saves about 5 s per width, within run-to-run noise at 1,600 px: the five-width run took 7 min 46 s against v38's 7 min 58 s, so it does little for the gate's time. Decline it to keep the audit as it is, and 7 to 9 then rebase mechanically. Risk: low.
7. **Layer facts in one table** (`LAYER_FACTS` beside `LAYERS`): each layer's group, year, pulse, squares and national marker. The id tests in `GROUPS`, `layerYear`, `syncYearRow` and the two id sets now read the table. The audit reads the facts from the page, so a new layer gets its audit states without an audit edit, and it holds the nine existing layers to your decided facts, so a changed fact is a finding. Risk: low.
8. **One card list** (`CARD_LIST`) from which the reading blocks, the pop-out charts and the redraws come. The audit checks it against the page's HTML and finds the reading blocks and pop-out charts in the DOM, so a new card is one entry, its HTML, its reading text and its draw function. Risk: low.
9. **A per-state record from the audit** (`--states-out`), so a change's boxes can be accounted for state by state. This pass used it to explain patches 6 and 7. Risk: none, new option.
10. **Chart options** (`C.yearDots`): `log: false` for a linear axis, `ref` for the reference line, `yFmt` for the tick labels. The defaults draw as before. Risk: low.
11. **A checked table intake** (`R/motion/motion-intake.R`). An exported table is checked against a schema of general rules before it becomes a data file. A data-frame entry is for tests, and a pinned-CSV wrapper is for real exports. Risk: low, new file.
12. **README "How to add or change content"** for 7 to 11 and the new checks. Risk: none.
13. **Round 17's page-text fixes** (T01 to T22, below), the first real use of patch 1.

## The independent review

A reviewer read every patch, without writing anything. What it found, and what was done:

- **The proof tool compared frames in grey levels**, which can hide a one-step change in a single colour channel. It now compares every channel. The baseline and the earlier Stage 4 run were compared again per channel from their saved frames, and both stay identical.
- **The tool's verdict** now counts the pages' console errors and says what was compared. It survives a probe that returns nothing, and it reuses a base only from a run that served the same address under the same label. `--compare-only` compares a run's saved files again.
- **Patch 13 now carries the rebuilt guide and glossary files**, so applying it leaves no stale file for the checks to report.
- **The glossary builder writes new files and renames them over the old.** A run in a proof copy therefore cannot write through a data link into the lab's files. A missing chapter file is reported instead of stopping the audit.
- **The audit checks the page against your decisions:** the nine layers' facts are pinned to them, so a changed fact is a finding and a new layer is listed. It also checks the card list against the page's HTML, and it takes the reading blocks and the pop-out charts from the page's DOM. The wire's speed is pinned again at 60 px/s, since no data refresh changes it.
- **Smaller fixes:** `microYear` reads the layer facts; the intake refuses a rule that names a missing column and a years rule without its range; the text snapshot reads every card's reading block from the page; and the comments the review named are corrected.
- **Kept as they are:** the hidden-frame load's poll (its result is unused, and at worst it waits its 4 s), and the density layer's 2021 test inside the hit test, which is a detail of that layer's branch.



## How this pass ran

- **The copies.** On `main`, with no branch or worktree. HEAD's files were copied to `build/round-18/base/` and `trial/`, each with `data/` as links to the lab's files. The data files a builder wrote were copied in first. After every builder run, the lab's tracked data, scripts and publish copies were checked unchanged.
- **The patches.** `patches/0001` to `0013` are diffs against HEAD, written from a chain of stage trees (`stage/p00` to `p13`). They were checked with `git apply` alone and in order, the second in a folder outside the repository, and in order they reproduce the trial file for file. Patches 1 to 5 and 10 to 12 apply alone. Patches 6 to 9 build on patch 5's audit edits, and patch 13 builds on 4 and 5.
- **The proofs.** They ran in headless Brave on 127.0.0.1, and every browser removes its profile. Two runs of mine were stopped part-way: one started with a plain `&`, which died with its shell, and one kill that matched its own shell. Their four orphaned browsers and five profiles were stopped and removed, and /tmp holds none now. Part of the first job outlived its shell and ran beside the restarted gates, so those outputs are set aside as `*-mixed` and not used. The gates above come from one run of one pipeline.
- **The agents.** One subagent, the reviewer, read the patches and wrote nothing. Its brief carried your personal-data rule word for word, and no web request was made.

## Not done, and why

- **The search queries (H9).** Today they match 42, 6, 1 and 89 firms, and the page shows at most ten, so they break only when a query matches no firm. The audit now checks the page's hits against the set the names give and says when a query matches none. The queries themselves were not replaced.
- **`ensureData`'s file lists stay in code.** Each file loaded on first use has its own decoder, so a facts entry would not save a step.
- **No `layers.json` registry and no per-layer modules.** Neither makes a proof cheaper than the layer facts do.
